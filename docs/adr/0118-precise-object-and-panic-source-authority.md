# ADR-0118: Precise Object and Panic Source Authority

- Status: Accepted
- Date: 2026-11-09
- Refines: ADR-0068, ADR-0082, ADR-0092, ADR-0096 and ADR-0117
- Supersedes in part, after separate Acceptance and merge: prior-record
  conservation for the fifty explicitly identified object payload/unit
  metadata tuples; no historical value, class or comparison changes

## Context

EV01-C08 implementation #238 has independently merged. Its 453 additional
names preserve every predecessor fact and all seven committed claims.
OBJ01's resumed read-only research found two different remaining boundaries.

Fifty existing portable object identities have an unrelated 29-path
fallback, including CMake and the shared C inspector, but no physical
object source. These are 48 function-body identities, their aggregate
signature identity and the complete reconstructed-source identity.
The source gate uses literal strings with `.split()` and a source-set
alias; the generic literal collection cannot recover its ownership map.
The directory move is a second obstacle to treating its flat paths as
current files.

Separately, panic stack proof compares complete projected source files
at three existing boundaries. Five selected-provider units and nine fault
prefix units overlap in three units; the trace-fixture getter branch also
checks the runtime unit. These are eleven distinct source policies,
including the hart-context owner that OBJ01 must eventually change.
Their coarse PLAT03 declaration does not provide individual names for
these comparisons.

The [fixed-source study](../research/object-and-panic-source-authority-gap.md)
pins both defects to #238. Neither relaxing source guards nor putting
independent CMake/parser inputs into a runtime candidate is an acceptable
way to proceed.

## Decision

After separate review, Acceptance and merge, implement the
[object and panic source-authority contract](../architecture/object-and-panic-source-authority.md)
as the sole EV01-C09 prerequisite. OBJ01 design remains blocked and its
implementation pending until this pair merges.

### Repair fifty existing bindings

Keep the original keys, families, owners, kinds, scopes, authority classes
and evidence values. Change only `payload_paths`, `primary_unit` and
`consumer_units` for:

- the 48 `BASELINE_BODIES/0/<original-name>` records in the object source gate;
- its `BASELINE_SIGNATURES/0` record; and
- its `BASE_CORE_DIGEST` record.

Each body binds its actual portable C owner. The signature aggregate binds
all nine portable C owners. The byte reconstruction binds those nine
sources and the private header, not just the facade.
Every record retains the original assertion-owner module.

Decode only the admitted portable ownership declaration and existing
directory map. A dedicated closed reader may recognize the existing
literal string's argument-free `.split()` spelling and literal string
lists in that declaration. Do not execute it, extend the shared literal
reader, interpret arbitrary Python, or change the frozen source gate.

### Name eleven existing panic source policies

Add one literal-only declaration and the family
`panic-trace-source-admission`. Each `TRANSPORT_IDENTITY` names one exact
source file, the original projection/reference and every existing
assertion function that checks that same equality.

The shared units have one identity each, with every consumer, not
duplicate identities. The runtime row also names `checked_source_record`'s
trace-fixture getter branch. Bind the actual assertion owner
`tools/stack_bound_fatal.py`. Preserve the exact comparison after
`project_trace_runtime`, including the runtime test-registry guard
projection; a hash of the unprojected current file is not equivalent.

This registration changes no source admission, machine-effect proof,
frame/call closure, fault route, stack epoch or budget.

### Separate historical metadata from current authority

The resulting current catalog has 5,851 records in twenty-five families.
All 5,840 predecessor identities and values remain. Exactly fifty old
metadata tuples change; the other 5,790 complete old records and
twenty-three unaffected old family fingerprints remain identical.
Only the old `kernel-structure` fingerprint changes, and one new family
fingerprint is added.

Independently freeze complete before/after/new records from the fixed
sources before any implementation edit.

A bounded inverse first checks the exact corrected metadata, then restores
only those fifty old metadata tuples for historical comparison.
MEM04 and MEM05 must still validate the complete current inventory before
that inverse and their existing positive predecessor-family selection.
Preserve MEM04's nineteen families, 4,774 records and original complete
digest, and MEM05's twenty-two families, 5,379 records and original
complete digest. Current transition validation never uses the inverse.

Preserve all seven committed claims and 185 retirements without author
journals. The inverse grants no new source permission and cannot discard
an invalid current addition.

## Acceptance

Require genuine missing-subject/missing-identity Red after positive and
negative controls for the existing assertions. Green proves all fifty
corrected records and eleven new records against independently fixed
expectations, strict declaration/path failures, unchanged old values,
exact historical recovery and current-before-historical rejection.

The complete current native, target, image, stack and author gates remain
required, followed by independent implementation review before the first
permanent implementation commit. Publish only identical reviewed and
merged content and verify fresh journal-free committed/main authority.

## Phase boundary and non-goals

This Accepted design contains documentation only. No code, test, model, fixture,
harness, build scaffold or reusable executable prototype precedes its
separate review, Acceptance and merge.

No object, hart, stack or scheduler algorithm is selected by this
prerequisite. It changes no runtime source, public layout/API, current
source guard, historical expected hash, authority class, retirement,
transition state machine, shared C parser, compiler, deadline, capacity,
stack/image budget, hosted-CI acceptance or runtime-DAG edge.

Native/target object-body families and unrelated conservative bindings
are not swept into this repair.

## Design review disposition

Initial independent read-only review found one High omission: MEM04's
historical predecessor comparison needs the same checked metadata inverse
as MEM05. It also found one Medium omission: the runtime source has a
third actual consumer in the trace-fixture getter branch.

The author verified both in the fixed current source and corrected the
contract, study and implementation boundary. Correction review inspected
staged tree `a7ae23836812f29d198f27ab82e9db3656de6fe0` and its matching
four FRESH/exit0 documentation/diff results. The reviewer reported:
"Both the High and Medium findings are closed. No substantive design
issue remains." No targeted reproduction or author-gate rerun was needed.

Acceptance records this design result, not a metadata implementation or
OBJ01 runtime correction. Separate design merge still precedes the
dependent implementation; OBJ01 design remains blocked until that
implementation separately merges.

## Alternatives

- Retire the broad fallback: rejected; it omits the subject and overlaps
  immutable independent inputs.
- Rewrite expected hashes from corrected kernel code: rejected as circular.
- Register a duplicate object identity: rejected; correct the existing
  identity's metadata instead.
- Retire PLAT03's entire coarse declaration: rejected; independent fatal
  and stack obligations must remain.
- Relax the shared literal parser: rejected; this declaration has a small
  closed spelling that needs no general evaluator.
- Project away unknown current facts: rejected; historical recovery starts
  only after complete current validation.
