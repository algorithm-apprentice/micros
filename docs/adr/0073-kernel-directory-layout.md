# ADR-0073: Kernel Directory Layout

- Status: Accepted
- Date: 2026-10-17
- Refines: ADR-0002, ADR-0025, ADR-0031, ADR-0032, ADR-0033, ADR-0034,
  ADR-0051, ADR-0064, ADR-0065, and ADR-0072
- Supersedes in part: after acceptance, the physical `kernel/` placements
  and include-operand byte freezes in ADR-0053 through ADR-0056,
  ADR-0059 through ADR-0062, and ADR-0066 through ADR-0070, solely for
  the exact directory transport below. Their logical owners, complete
  original-source oracles, private directions and behavior remain binding.

## Context

The source-audit implementation outcomes are merged through QEMU runner
#146, `f524a234f7bef07c69f15eba6f388ca5d017625c`. Its squash tree equals
the independently reviewed tree, current full/reuse acceptance is complete,
main fast-forwarded clean and obsolete branches are removed.

All 373 tracked kernel files still occupy one directory: 274 C sources and
99 headers. Their responsibility owners are now explicit, but their
physical names mix portable mechanisms, privileged adapters, bootstrap,
hardware, fatal diagnostics and sixteen target-evidence families.
This is a directory-navigation outcome, not another function decomposition.

The [fixed MINIX layout trace](../research/minix-kernel-directory-layout.md)
separates generic kernel entry, explicit kernel-call owners, architecture
selection and qualified private includes. Its particular hierarchy, broad
header surface, BSD make machinery and deferred functionality are not
requirements for `micros`.

## Decision

After independent design review, acceptance and separate merge, apply the
exact [kernel directory contract](../architecture/kernel-directory-layout.md).
Only the design task is active now; its paired implementation stays pending.

Move the closed 373-file inventory without renaming basenames, moving
functions between their accepted logical owners, changing bodies or
introducing new runtime interfaces. Fourteen production directories hold
231 files; sixteen target-evidence directories hold 142. No C/header file
remains in the old flat root and no compatibility forwarding file, copy,
hard link, symlink or generated alias tree remains there.

### Exact source and include identity

The reviewed predecessor, fixed partition, counts, special cases and
private include policy are normative in the source contract. Implementation
freezes literal old/new paths, original bytes, include operands and all
consumers before rewriting. Unknown, missing, duplicate or linked members
fail closed; the partition is not a glob rule for future sources.

Supported `include/micros` headers remain byte-exact. Moved private headers
retain their guards, types, constants, declarations and existing inline
bodies. Only exact quoted kernel-private include operands change to their
new repository-qualified locations. Existing private include visibility
does not become a public include or a wider kernel API.

All original source body, type, storage, CPP, generation, authority,
failure, publication, lifetime, case, model, marker and budget contracts
remain binding. A bounded host-only actual-source transport restores the
old logical include operands before existing immutable byte/source oracles.
It reads actual current owners, never an archived source body or Git blob.
The shared C inspector and old parser algorithms are not rewritten.

### Runtime diagnostics, build and generated evidence

Preserve the existing target-relative and native-absolute `__FILE__`
values and every `__LINE__` value. Fixed C-only macro prefix maps cover the
thirty new directories; the target's existing file/debug prefix map stays
unchanged. No `#line` directives, panic-wrapper changes or fake source
filenames are inserted into C/header bodies.

CMake retains all target/source-set names, ordered consumer operands,
link order, compile guards, generated-output names, commands and budgets.
Four existing native consumers gain only the private repository-root
include operand required by qualified private headers. Twenty-one native
kernel consumers and `micros` receive only the exact diagnostic maps.
Nine generators change only their emitted kernel-fixture include operand;
all remaining generated bytes and generator algorithms restore before old
expected values. No topology, image quota or runtime data changes.

### Selection and real validation eligibility

Keep the existing classifier algorithms. A finite data-only expansion of
the existing 88 equivalence rows adds physical aliases to their old logical
owners and appends 333 exact singleton rows. All 373 relocated paths must
independently retain their original full-tier, QEMU, slow-model and image
dimensions and every tier's complete command plan. Unknown-path fallback,
Git discovery and final-candidate source identity are unchanged.

The admitted CMake digest may change only after the complete current
`730a6dd6...` recipe reconstructs from actual CMake through the exact path,
four include-operand and two diagnostic-option-block inverse. Compose
directory source/recipe/metadata transport before earlier accepted
projections; never replace their expected hashes or weaken evidence.

Native, smoke and TTY-image eligibility must remain real under the
unchanged closed profiles. No collector, execution, default-configuration,
namespace, receipt, reusable-workflow, coverage or cross-HEAD relaxation is
authorized.

## Evidence and phase barrier

Design contains documents only. It authors no code, test, model, harness,
fixture, build scaffold or reusable prototype.

The separate implementation starts with structural Red, immutable complete
source/include/consumer/recipe/classification inventories and independent
positive/negative transport fixtures. Its exact 373-entry physical owner
migration may only shrink and must finish literal empty; every previously
completed subsystem migration remains empty. There is no new semantic
function migration or line-count-only split.

Small green responsibility slices retain their narrow existing evidence.
Final acceptance requires the complete current fresh author plan,
additional actual same-original-full-producer native/smoke/TTY-image reuse,
clean independent read-only implementation review, identical reviewed
squash tree, main fast-forward and exact obsolete-branch cleanup.
Reviewers inspect author evidence rather than routinely repeating suites.

## Non-goals

No kernel/service/application behavior, public ABI, private declaration,
state, allocation, generation, authority, scheduler policy, trap/return
custody, IRQ, deadline, model, parser or algorithm change. No source
basename rename, new function decomposition, public include migration,
directory-per-function layout, runtime discovery, import/filesystem
framework, recovery, compatibility layer, build system replacement,
new executable/CTest/workflow or production init/shell work.

## Alternatives

- Keep a flat 373-file root: rejected because the existing cohesive owners
  now permit a bounded navigable hierarchy without another semantic split.
- Copy MINIX's hierarchy: rejected; architecture, authority and MVP scope
  differ under existing Accepted ADRs.
- Move production but leave target evidence interleaved: rejected; evidence
  ownership should be visible without changing its executions.
- Retain forwarding headers or an old generated include tree: rejected;
  actual physical sources and dependencies must have one owner.
- Change diagnostics to new physical paths or insert `#line`: rejected;
  existing observable location/line contracts can be retained through
  bounded compiler metadata instead.
- Rewrite selection or erase old source oracles: rejected; exact existing
  aliases and finite actual-source inverses preserve stronger evidence.

## Design review disposition

Complete independent read-only review inspected the nine-document proposal,
relevant Accepted authority, closed current inventory and partition,
private include/consumer feasibility, canonical compiler diagnostics,
actual-source/generated/recipe/metadata transport and exact current
four-command author evidence. It reported: "No significant issues found in
the reviewed changes. No substantive design issue remains."
Targeted reproduction: None.

Acceptance records that clean design result, not implementation completion.
The paired implementation stays pending until this separate design merges.
