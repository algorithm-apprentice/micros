# ADR-0082: Evidence Authority Transition

- Status: Accepted
- Date: 2026-10-19
- Refines: ADR-0033, ADR-0034, ADR-0051 through ADR-0073, and ADR-0080

## Context

The source-decomposition program preserved existing behavior by freezing
earlier `micros` source bodies, ASTs, token streams, data, and CMake recipes.
Those gates correctly prove that a file move or task split reconstructs the
reviewed pre-split implementation.

The complete MINIX baseline audit found that many preserved implementations
are not the required structural and algorithmic baseline. A historical
`micros` body identity therefore cannot also be the correctness authority for
the correction that must change that body.

Two unsafe responses are possible:

1. keep the historical identity unchanged and block the required correction;
2. regenerate the identity from the edited worktree and let the correction
   approve itself.

The first prevents progress. The second destroys independent evidence.
B14-F001 requires one fail-closed transition mechanism before any frozen-body
runtime correction begins.

## Decision

### Separate authority classes

Executable evidence uses these distinct authority classes:

1. **Transport identity** proves that a behavior-preserving decomposition
   reconstructs an earlier reviewed `micros` source, data, or recipe.
2. **Permanent structural invariant** proves current ownership, dependency
   direction, private boundaries, bounded storage, recipe membership, or
   another design invariant that remains valid across behavioral correction.
3. **MINIX-derived baseline oracle** proves required behavior, structure,
   algorithm, mutation order, complexity, or storage independently from the
   production implementation under test.
4. **Artifact contract** proves deterministic generated bytes or ELF shape
   from independently specified inputs.

A transport identity is never baseline certification. An artifact digest is
not a production-algorithm oracle. A correction changes only the authority
whose reviewed contract it supersedes.

### Fixed authority sources

A baseline oracle derives expected facts from:

- the fixed local MINIX commit;
- an Accepted `micros` adaptation or safety decision;
- a small independent reference model;
- explicit operation/topology/stack bounds in the accepted design; or
- deterministic external artifact policy.

It must not derive expected values by inspecting the edited production body,
serializing its current AST, copying its current output into a fixture, or
recomputing a digest from the candidate worktree.

Transport identities retain their original reviewed commit/tree or immutable
literal source. Moving the pin to the candidate is not a transition.

### Per-correction transition record

Every correction that changes a frozen identity declares one exact transition
record before implementation. The record contains:

- stable transition ID and owning finding IDs;
- merged design ADR/contract;
- affected transport family and exact identity keys;
- immutable transition owner and exact merged design commit/tree/document;
- retained permanent invariants;
- planned retirement identity keys;
- replacement baseline-oracle test IDs, property names, and structured
  MINIX/Accepted-adaptation/model provenance, including the exact planned
  retirement identities replaced by each oracle;
- downstream audit units requiring re-certification; and
- ordered Red, Green, and author-recertification evidence events.

The only states are:

```text
TRANSPORT_ONLY
-> REPLACEMENT_REGISTERED
-> CORRECTION_ACTIVE
-> RETIREMENT_READY
```

`TRANSPORT_ONLY` is the initial state. `REPLACEMENT_REGISTERED` requires the
accepted design and complete replacement-oracle declaration, but does not
claim implementation success. `CORRECTION_ACTIVE` is allowed only on the
fresh implementation branch after the replacement Red result is recorded.
`RETIREMENT_READY` requires the corrected implementation, Green replacement
oracle, retained invariant checks, and affected-unit author evidence.

State is derived from the immutable plan and ordered events; callers do not
supply a mutable state field. Skipping an event, changing the transition
owner/plan, or mutating an earlier event is an error. Independent review stays
outside this state machine as the merge gate for the exact author-validated
candidate.

The committed inventory may classify a closed authority family through a
deterministic key extractor and explicit exceptions rather than duplicating
thousands of digest literals. Validation still materializes every individual
key and requires one class and owner. An open filename glob or family without
complete observed/declaration equality is not an inventory.

### Red-Green authority order

The required order is:

1. keep every existing transport identity active;
2. add the independent replacement oracle;
3. demonstrate locally that it fails for the expected audited divergence;
4. implement the minimum correction;
5. make the replacement oracle pass;
6. after Green, run affected-unit author recertification in one transaction
   that provisionally suppresses only the planned retirement identities;
7. on recertification success, append its hash-chained event, derive
   `RETIREMENT_READY`, and retire only the planned identities;
8. keep all unrelated transport identities and permanent invariants active,
   then run the post-terminal milestone gate; and
9. submit the exact green candidate to independent implementation review.

The Red state may remain local under the existing workflow. The first
permanent commit remains green and includes the replacement oracle, minimum
correction, and exact authority transition when separating them would leave a
broken commit.

### Partial retirement

Retirement is granular. A correction may retire one function-body digest
while preserving:

- unrelated bodies in the same historical family;
- source-set reconstruction;
- single-definition and owner checks;
- private-header and dependency-direction checks;
- static-storage, automatic-storage, and case inventories;
- generated-byte or ABI identities not changed by the correction; and
- planner/recipe mappings outside the changed outcome.

Deleting or rebaselining an entire structural gate because one identity
changed is prohibited.

### Fail-closed behavior

The evidence authority implementation rejects:

- an affected frozen identity with no transition record;
- a retired identity with no replacement oracle;
- a replacement oracle with no accepted design/finding owner;
- duplicate identity or oracle ownership;
- duplicate family ownership hidden by family-qualified fact names;
- a candidate-derived expected digest/model/result;
- an unknown retained or retired identity key;
- retirement before the correction state and re-certification evidence agree;
- silent removal of a permanent invariant;
- a current source-layout family missing from the authority inventory; and
- a current W01/W44 evidence module outside declared family ownership or an
  explicit non-identity exception;
- changed oracle/model/fixture/authority inputs after the Red observation;
- a skipped, not-run, aggregate-only, or nondiscriminating replacement oracle;
- any planned-retirement identity without a covering expected Red failure;
- a missing, skipped, not-run, failing, extra, or projection-mismatched
  affected-unit recertification result;
- an empty or under-declared recertification-unit set relative to affected
  identity ownership, finding-unit prefixes, and B14 consumer mapping;
- a finding ID not owned by the declared correction task;
- an omitted, extra, borrowed, or split finding set relative to the declared
  correction task;
- candidate-source drift between Green and author recertification;
- extra inventory rows without a real test/source authority.

Failure is explicit. There is no automatic rebaseline, best-effort admission,
or success-shaped fallback.

### EV01 implementation boundary

EV01 implementation adds only evidence infrastructure and documentation
recertification. It:

- inventories every current historical source/data/recipe identity family;
- classifies each identity as transport, permanent invariant, artifact
  contract, or already independent baseline oracle;
- provides the typed transition declaration and fail-closed validator;
- proves positive and negative transition fixtures;
- marks every existing historical identity `TRANSPORT_ONLY`; and
- updates B14 evidence ownership.

It does not retire a production identity, change production code, implement an
operation counter, add stack tooling, or perform any later correction.

### Acceptance

EV01 design is complete when implementation can proceed without inventing:

- authority classes;
- transition fields or states;
- Red-Green ordering;
- retirement granularity;
- failure precedence;
- source-family coverage; or
- review and re-certification requirements.

EV01 implementation is complete when every current authority family is
classified exactly once, malformed transitions fail, a representative
positive transition preserves unrelated identities, documentation and native
evidence pass, and independent review reports no substantive issue.

## Consequences

- Historical decomposition evidence remains useful and auditable.
- Runtime corrections cannot approve themselves by rewriting hashes.
- Each correction carries explicit replacement evidence before identity
  retirement.
- Structural test maintenance becomes more deliberate, but correction review
  can distinguish source transport from baseline correctness.
- EV02 operation counters and later correction tests gain a stable authority
  mechanism.

## Alternatives considered

### Delete historical source-layout tests

Rejected. They retain valuable ownership, recipe, and decomposition evidence.

### Recompute digests after every correction

Rejected. Candidate-derived expectations are circular.

### Keep both old and new authorities permanently

Rejected. An intentionally changed historical body would make the suite
permanently red or force hidden exceptions.

### Let each correction invent its own transition

Rejected. Inconsistent retirement rules would recreate the authority gap.
